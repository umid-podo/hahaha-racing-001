# 레이싱 게임 — 웹앱 기획 초안

이번 산출물은 기획과 캐릭터 콘셉트다. 게임 코드·실행 화면·배포는 포함하지 않는다. 원본 해석은 [01-source-notes.md](01-source-notes.md)를 참조한다. 아래에서 ‘제안’으로 표시한 내용과 수치는 원본에 없는 보완안이며 플레이테스트 전 초깃값이다.

## 게임의 중심 경험

웃는 얼굴의 작은 카트를 움직여 부스터를 밟고, 상대의 공격을 피해 1,000m 결승선에 먼저 도착하는 2~6인 캐주얼 레이싱 게임. 복잡한 운전 기술보다 쉬운 터치 조작과 친구 사이의 역전 경쟁에 집중한다.

- 한 판 예상 시간: 약 60~90초를 제안.
- 승리 조건: 가장 먼저 1,000m 도달. 첫 도착이 확정되면 전원 레이스 종료.
- 반복 흐름: 인원 선택 → 출발 → 이동·부스터·공격·회피 → 승리 연출 → 승수 확인 → 다시하기.
- 캐릭터별 성능 차이는 두지 않는 것을 제안. 색과 번호로 플레이어를 구분한다.

## 화면 흐름

| 화면     | 주요 내용                            | 다음 동작             |
| ------ | -------------------------------- | ----------------- |
| 타이틀    | 레이싱 게임, 원작 카트 캐릭터, 시작            | 인원 선택             |
| 인원 선택  | 2~6명, 선택 상태, 선택 버튼               | 레이스 준비            |
| 레이스 준비 | 플레이어 색·번호, 터치 영역, 짧은 조작 안내, 시작   | 3·2·1 출발 카운트다운 제안 |
| 레이스    | 카트, 공격 칸, 부스터, 거리·순위·공격 보유 상태    | 첫 결승 도달           |
| 승리 연출  | 승자는 양팔을 들고 나머지는 아쉬운 표정           | 원본대로 3초 뒤 결과      |
| 결과     | 승자, 플레이어별 이번 순위와 세션 승수, 다시하기·타이틀 | 재경기 또는 타이틀        |

결과의 ‘이번 순위’는 제안이다. 원본대로 첫 도착 시 종료하므로 미완주자는 종료 순간의 누적 거리로 정렬하고, 기록은 ‘미완주’로 표시한다. 도착 시간을 만들어 표시하지 않는다.

## 레이스와 조작 제안

**사용자 확정:** 아이패드·휴대폰에서 한 기기를 여러 명이 동시에 터치한다. 그림체는 원본 손그림 느낌을 살린 깔끔한 2D다. 온라인 방 접속이나 AI 상대는 첫 구현 범위에 포함하지 않는다.

원본의 ‘터치한 동그라미로 이동’을 살리면서 끝없이 전진하기 위해, **자동 전진 + 자기 영역 안에서 터치·드래그한 위치로 회피 이동**을 제안한다. 손가락을 떼어도 기본 전진은 유지한다. 연타 속도로 승부하지 않는다.

- 카트의 경주 거리와 화면 안의 위치를 분리한다. 배경은 진행 방향으로 흐르고 카트는 화면 안에 머문다.
- 터치 지점에 플레이어 색의 동그라미를 표시한다. 카트는 순간이동하지 않고 정해진 이동 속도로 따라간다.
- 카트 전체가 자신의 주행 영역 밖으로 나가지 않도록 경계를 제한한다.
- 코스는 복잡한 커브 없는 직선 1개를 첫 버전으로 제안한다.
- 전체 진행은 0~1,000m 진행 막대로 보여준다. 색과 플레이어 번호를 함께 표시한다.
- PC 조작은 플레이 방식 확정 후 설계한다. 한 대의 키보드로 6명이 동시에 조작하는 방식은 기본안에 넣지 않는다.

## 공격

원본의 ‘공격 칸 획득 → 상대 터치 → 날아가는 공격 → 회피 가능 → 명중 시 3초 감속’을 유지한다.

1. 공격 칸을 지나면 공격 1개를 보유한다는 규칙을 제안한다.
2. 보유 중에는 공격 가능한 상대의 번호·색을 강조한다.
3. 상대 선택 시 공격을 소비하고 대상에게 투사체가 날아간다.
4. 발사 시점의 상대 위치로 날아가는 비추적 공격을 제안한다. 경고 방향과 충돌 예상 위치를 보여줘 회피 가능성을 확보한다.
5. 명중 시 3초 감속. 파괴나 탈락 없이 계속 달린다.

같은 터치가 조향과 상대 선택을 동시에 일으키지 않도록 공격 선택 상태를 별도로 둔다. 자기 조작 영역에 전용 상대 선택 버튼을 두고, 공격 획득 후 상대 번호를 터치하면 발사한다. 이는 상대를 터치한다는 원본 의도를 유지하면서 다른 사람의 손이나 조작 영역을 침범하지 않게 하는 보완안이다. 공격 버튼 터치는 조향 입력으로 전달하지 않는다.

## 한 기기 멀티터치 화면 설계

가로 화면을 기본으로 제안한다. 각 패널은 위쪽의 주행 화면과 아래쪽의 조작 공간으로 이루어지며, 자기 카트와 장애물·투사체를 보여준다. 패널마다 자동 스크롤되는 동일한 길이의 코스를 달리고 전체 순위는 공통 진행 막대에서 비교한다. 상대에게 쏜 공격은 해당 상대 패널에 경고 후 진입한다. 카트끼리 직접 부딪히는 규칙은 넣지 않는다.

| 인원 | 패널 배치 제안 | 권장 기기 |
|---|---|---|
| 2명 | 좌우 2열 | 휴대폰·아이패드 |
| 3명 | 3열 1행 | 아이패드 |
| 4명 | 2열 2행 | 아이패드 |
| 5~6명 | 3열 2행, 5명은 마지막 칸에 조작 안내 | 아이패드 |

휴대폰에서도 2~6명 선택은 유지하되 3명 이상은 조작 공간이 좁다는 안내와 2명 권장을 표시한다. 5~6명 배치는 태블릿을 테이블에 놓고 사용하는 상황을 기준으로 검증한다. 첫 버전은 모든 패널을 같은 방향으로 표시하고, 좌석별 회전은 후속 사용성 개선으로 둔다.

입력 규칙 제안:

- 손가락이 처음 닿은 패널에 해당 터치를 귀속하고, 옆 패널로 넘어가도 다른 사람을 조작하지 않는다.
- 플레이어마다 조향 손가락 1개를 기본으로 한다. 공격은 잠시 조향 손가락을 떼고 같은 패널의 상대 버튼을 누르는 방식으로도 가능해야 한다. 손을 떼는 동안 마지막 위치와 자동 전진을 유지한다.
- 공격용 추가 터치는 지원하되 필수가 아니다. 불필요하게 많은 손가락을 요구하지 않는다.
- 손가락 아래에 캐릭터가 가려지는 문제를 줄이기 위해 아래 조작 공간의 상대 위치를 위 주행 영역에 대응시킨다. 조작 공간에는 원본의 터치 동그라미를 표시한다.
- 페이지 스크롤·확대 제스처와 경기 입력이 충돌하지 않도록 경기 영역의 터치를 처리한다. 앱 전환·터치 취소 시 입력을 해제하고, 복귀 후 전체 경기 재개 카운트다운을 제안한다.
- 결과 화면의 다시하기 버튼은 여러 사람이 동시에 눌러도 한 번만 처리한다.

기기별 동시 터치 수와 시스템 제스처의 영향을 실제 아이패드·휴대폰에서 확인해야 한다. 6명이 각자 한 손가락을 쓰는 상황을 필수 확인 대상으로 삼으며, 모든 기기가 6인 동시 입력을 지원한다고 가정하지 않는다.

## 부스터와 초기 밸런스 제안

| 항목 | 초깃값 | 의도 |
|---|---|---|
| 기본 전진 | 14m/s | 아무 효과 없이 약 71초에 완주 |
| 부스터 | 속도 ×1.4, 2초 | 즉각적인 추월 기회 |
| 공격 명중 | 속도 ×0.6, 3초 | 원본의 감속 지속시간 반영 |
| 공격 보유 | 최대 1개 | 조작·표시 단순화 |
| 재피격 보호 | 명중 후 1초 | 집중 공격으로 조작 불가능해지는 상황 완화 |
| 공격 회피 예고 | 도착 약 0.8~1.2초 전 | 보고 피할 여유 확보 |

부스터는 중첩 배율 없이 지속시간만 갱신한다. 감속은 더 느려지는 중첩 없이 지속시간만 갱신하며, 보호시간 중 피격은 무시한다. 부스터와 감속이 함께 걸리면 배율을 곱한다. 모든 수치는 테스트에서 조정한다.

공격 칸은 원본대로 랜덤 배치하되 완전한 무작위 대신 출발 100m·마지막 100m에는 배치하지 않는 것을 제안한다. 같은 경기 안에서 각 플레이어가 얻을 수 있는 기회 수는 비슷하게 하고 좌우 위치를 바꾼다. 부스터도 통과를 선택할 수 있는 크기와 위치로 배치한다.

## 승리와 재경기

- 첫 결승 도달 시 입력과 경기 시간을 함께 멈추고 승리 연출을 시작한다.
- 같은 판정 시각에 결승선을 통과하면 공동 1위로 처리하고 각자 승수 +1을 제안한다.
- 원본의 결과 표기를 따라 ‘세션 누적 승수’를 기본 지표로 제안한다. ‘연승’과는 다른 개념임을 명시한다.
- 다시하기: 인원·색·세션 승수 유지, 거리·공격·부스터·감속·코스 배치 초기화.
- 타이틀: 세션 승수 초기화. 원본의 ‘연승 취소’를 세션 종료로 해석한 제안이다.
- 경기 중 실수로 나가는 일을 줄이기 위해 타이틀 복귀 시 확인창을 제안한다.

## 캐릭터와 화면의 미술 방향

원본의 동그란 얼굴, ∧ ∧ 눈, ω 입, 가는 몸, 작은 운전대와 낮은 카트를 캐릭터의 기준으로 삼는다. Blue와 Red는 원본에 직접 등장하는 기본 캐릭터다. 나머지 4명은 같은 실루엣에 노랑·초록·보라·주황 카트를 적용하는 확장안을 제안한다. 색은 능력 차이를 뜻하지 않는다.

캐릭터가 작게 보일 때에도 표정과 카트 색이 구분되어야 한다. 번호 1~6은 실제 게임 UI에서 표시한다. 캐릭터 생성 이미지에 작은 글씨를 넣지 않는다. 주행·기쁨·아쉬움 3가지 상태부터 제작하고, 피격과 부스터는 외부 효과로 확장한다.

생성 이미지는 **디자인 확인용 콘셉트**다. 실제 구현 때 사용할 개별 PNG, 일정한 시점과 중심점의 애니메이션 프레임, 충돌 영역은 후속 제작 범위다.

## 첫 구현 범위와 완료 기준

첫 구현에서는 타이틀, 2~6명 설정, 코스 1개, 터치 이동, 공격·회피·감속, 부스터, 1,000m 결승, 3초 승리 연출, 세션 승수, 다시하기·타이틀까지를 포함한다. 계정·상점·캐릭터 성장·외부 랭킹·추가 코스는 확장 항목이다. 연결 방식은 아래 결정 사항에 맞춰 범위를 조정한다.

후속 구현의 확인 기준:

- 선택한 인원 전부가 서로 입력을 빼앗지 않고 조작할 수 있다.
- 카트가 화면 밖으로 벗어나지 않는다.
- 공격은 획득 후에만 발사되며, 회피할 수 있고, 명중 시 감속이 3초 후 해제된다.
- 부스터 효과가 표시되고 만료된다.
- 첫 완주에서 게임이 한 번만 끝나고 3초 뒤 결과가 표시된다.
- 재경기에서는 승수가 유지되고 타이틀 복귀에서는 초기화된다.
- 화면 크기가 달라도 자기 조작 영역과 공격 대상 버튼을 혼동하지 않는다.

## 구현 전 결정 사항

한 기기 동시 터치와 깔끔한 손그림 2D는 사용자 확정 사항이다. 자동 전진, 패널 배치, 누적 승수 해석, 아이템 수치는 위 제안으로 시작할 수 있으나 원본의 확정 요구와 구별하여 유지한다. 후속 구현 전에 특히 ‘누적 승수’와 원본에 적힌 ‘연승’ 중 원하는 지표를 확인하면 좋다.
