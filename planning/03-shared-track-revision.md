# 보완 기획 — 공유 트랙, 공유 아이템, 속도감

첫 구현(`index.html`, `style.css`, `game.js`)을 플레이해 본 뒤 나온 보완 요구를 다음 개발 세션에서 바로 구현할 수 있도록 정리한 문서다. 이 문서는 코드를 포함하지 않는다. [02-game-design.md](02-game-design.md)와 충돌하는 부분은 이 문서가 우선한다.

표기: **확정** = 사용자 요구, **제안** = 구현을 위해 채운 보완안(플레이테스트 전 초깃값), **확인 필요** = 개발 전에 사용자에게 물어볼 것. 확인을 못 받으면 적힌 기본안으로 진행한다.

## 1. 확정된 보완 요구

1. **같은 트랙**: 지금은 플레이어마다 별도의 코스를 달린다. 모든 카트가 하나의 트랙을 함께 달리고, 각자의 화면에 다른 카트의 모습이 보여야 한다.
2. **아이템 선점**: 한 카트가 획득한 아이템은 다른 카트가 획득할 수 없다.
3. **속도감**: 지금보다 더 빠르게 달리는 느낌이 나야 한다.

유지되는 것: 한 기기 동시 터치, 플레이어별 패널(위 주행 화면·가운데 공격 버튼·아래 터치 화면), 2~6인 배치, 1,000m, 첫 도착 시 종료와 3초 뒤 결과, 세션 누적 승수, 손그림 2D, 입력 귀속 규칙, 일시정지와 재개 카운트다운.

## 2. 현재 구현과 달라지는 점

| 항목 | 현재 | 보완 후 |
|---|---|---|
| 트랙 | 패널마다 독립 코스. 다른 카트는 진행 막대에서만 보임 | 하나의 월드. 패널은 "자기 카트를 따라가는 카메라"이고 시야 안의 모든 카트를 그린다 |
| 카트 위치 | 경주 거리 `dist`와 화면 속 위치 `x, y`가 분리됨 | 트랙 위의 실제 위치 하나로 통합 (3장) |
| 아이템 | 같은 거리·종류, 플레이어별 좌우 위치, 플레이어별 획득 여부 `taken[i]` | 월드에 하나만 존재. 먼저 닿은 카트가 가져감 |
| 공격 | 대상 패널 안에서만 경고·투사체 표시 | 월드를 날아가며 시야에 들어온 모든 화면에 보임 |
| 속도 | 14m/s, 화면 가로지르는 데 약 2.9초 | 수치와 연출을 함께 올림 (6장) |

02 문서에서 대체되는 문장: "패널마다 자동 스크롤되는 동일한 길이의 코스를 달리고", "상대에게 쏜 공격은 해당 상대 패널에 경고 후 진입", "카트의 경주 거리와 화면 안의 위치를 분리한다", "각 플레이어가 얻을 수 있는 기회 수는 비슷하게", 기본 전진 14m/s·약 71초. "카트끼리 직접 부딪히는 규칙은 넣지 않는다"는 유지한다.

## 3. 공유 트랙의 위치 모델

서로의 모습을 일관되게 보여주려면 "화면 속 위치"가 곧 "트랙 위의 위치"여야 한다. 그렇지 않으면 내 화면에서는 내가 앞인데 상대 화면에서는 상대가 앞인 모순이 생긴다.

**제안 (기본안 B — 2D 이동 유지):**

- 플레이어마다 `base`(자동 전진 누적 거리, m), `off`(터치로 움직이는 전후 오프셋, m), `lat`(좌우 위치 0~1)을 둔다. 트랙 위의 실제 위치는 `wx = base + off`다.
- 속도 효과(부스터·감속)는 `base`에 적용한다. 터치 화면의 가로축은 `off`, 세로축은 `lat`의 목표값이 된다. 조작감은 지금과 같다.
- 순위, 진행 막대, 결승 판정, 아이템·공격 판정은 모두 `wx`와 `lat`을 쓴다. 이렇게 하면 첫 구현의 한계였던 "결승선 그림과 판정 시점의 어긋남"도 함께 해소된다.
- 각 패널의 카메라는 자기 카트의 `base`를 따라간다. 화면 x = `anchor + (대상의 wx − 내 base) × ppm`. 자기 카트는 지금처럼 화면 안에서 움직인다.
- `off`의 범위는 화면 가로 12%~55% 구간으로 제한하는 것을 제안한다. 앞쪽 45%는 항상 전방 시야로 남긴다. 앞으로 나가면 실제로 앞서지만 아이템과 장애를 볼 시간이 줄어드는 선택이 된다.
- 전후 이동 속도는 좌우 이동보다 느리게 제한한다(제안: 전후 10m/s, 좌우는 현재 수준). 터치만으로 순간 가속하는 것을 막는다.
- 출발 시 모든 카트는 `wx = 0`, `lat = (i + 0.5) / 인원`으로 세로로 나란히 선다.

**대안 A (좌우 이동만):** 카트의 화면 가로 위치를 고정하고 터치는 좌우(`lat`)만 조종한다. 구현은 더 단순하지만 원본의 "동그라미가 있는 곳으로 감"이 1차원으로 줄고, 아이템을 먼저 차지하려는 앞지르기 조작이 사라진다.

> **확인 필요 ①** B(기본안)와 A 중 선택.

### 다른 카트 표시

- 시야 안의 모든 카트를 같은 크기·같은 그림으로 그린다. 부스터 불꽃, 감속 별, 피격 흔들림, 승리·패배 포즈도 모두에게 보인다. 그리는 순서는 `lat` 오름차순(뒤쪽부터).
- 자기 카트는 머리 위에 번호 표식(▼와 번호)을 붙여 구분한다. 색만으로 구분하지 않는다.
- 시야 밖의 상대는 화면 좌·우 가장자리에 색 원·번호·거리 차(예: `◀ 2 · 35m`)로 표시한다. 세로 위치는 그 상대의 `lat`에 맞춘다.
- 카트끼리 충돌은 없다. 겹치면 통과한다(02 문서 유지).

> **확인 필요 ②** 카트끼리 부딪히는 규칙을 원하는지. 기본안은 "없음".

## 4. 공유 아이템

- 아이템은 월드에 `{ wx, lat, type, takenBy }` 하나로 존재한다. `takenBy`가 정해지면 모든 화면에서 즉시 사라지고, 획득한 카트 색의 짧은 획득 연출을 모든 화면에 보여준다.
- 같은 프레임에 두 카트가 닿으면 칸 중심에 더 가까운 카트가 가져간다. 그래도 같으면 `wx`가 큰 쪽.
- 공격을 이미 보유한 카트는 공격 칸을 소비하지 않고 지나간다(현재 규칙 유지). 뒤따르는 카트의 기회가 된다.
- 판정 크기는 현재 체감을 기준으로 한다. 같은 경기의 패널은 모두 같은 크기이므로 공통 기하(패널 0 기준)로 계산하면 된다. 참고값(아이패드 4인 기준 환산): 획득 전후 ±3.5m·좌우 ±0.19, 피격 전후 ±2.8m·좌우 ±0.20.

### 선두 독식 방지 (제안)

선점 규칙을 그대로 두면 선두가 모든 칸에 먼저 닿아 부스터와 공격을 독차지하고, 그 공격을 뒤 사람에게 쏘는 악순환이 생긴다. 아래 두 가지를 함께 제안한다.

1. **줄 단위 배치**: 한 지점에 칸 하나가 아니라 가로로 나란한 줄을 놓는다. 2~3인은 줄당 2칸, 4~6인은 줄당 3칸. 줄 안에 부스터와 공격을 섞어 무엇을 먹을지 고르게 한다. 좌우 간격상 한 카트가 한 줄에서 두 칸을 먹기는 어렵다. 출발 100m와 마지막 100m에 놓지 않는 규칙은 유지한다.
2. **따라잡기 보정**: 선두와의 거리 25m마다 +2%, 최대 +10%의 속도 보정. 화면에 서로가 보이는 시간이 길어지는 효과도 있다.

> **확인 필요 ③** 따라잡기 보정을 넣을지. 기본안은 "넣음". 줄 단위 배치는 선점 규칙(확정)을 해치지 않으므로 기본 적용.

## 5. 공유 트랙에서의 공격

- 발사 조건과 상대 번호 버튼은 그대로 둔다.
- 비추적 원칙 유지. 단, 대상이 계속 전진하므로 충돌 예상 위치는 월드 고정점이 아니라 **발사 시점의 대상 위치를 대상의 `base`에 상대적인 값(`off`, `lat`)으로** 기록한다. 현재 구현의 `u, v` 기록과 같은 개념이다.
- 투사체는 공격자 위치에서 출발해 예고 시간(약 1.0초) 동안 예상 위치로 날아간다. 공격자가 대상 화면 밖에 있으면 공격자가 있는 쪽 가장자리(뒤면 왼쪽, 앞이면 오른쪽)에서 진입한다. 경고 표시도 그 방향에 띄운다.
- 투사체와 경고 원은 시야에 들어온 모든 화면에 그린다. 명중 판정은 지정한 대상에게만 한다(제안). 지나가던 제3자는 맞지 않는다.
- 감속 3초, ×0.6, 재피격 보호 1초는 유지한다.

## 6. 속도감

수치와 연출을 함께 올린다. 시야를 좁히면 속도감은 늘지만 상대가 화면에 보이는 시간이 줄어들어 요구 1과 충돌하므로, 시야는 조금만 줄이고 연출의 비중을 높인다.

### 수치 (제안)

| 항목 | 현재 | 제안 | 비고 |
|---|---|---|---|
| 기본 전진 | 14m/s | 20m/s | 효과 없이 약 50초 완주 |
| 부스터 | ×1.4, 2초 | ×1.6, 2초 | 체감 차이를 크게 |
| 화면에 보이는 거리 `viewMeters` | 40m | 36m | 화면 통과 약 1.8초(부스터 시 약 1.1초) |
| 속도 변화 | 즉시 | 0.25초에 걸쳐 가감속 | 밀려나가는 느낌 |

> **확인 필요 ④** 한 판 길이가 약 70초에서 약 50초로 줄어드는 것을 받아들일지. 1,000m는 원본 확정값이므로 길이를 유지하려면 연출만으로 속도감을 내야 한다. 기본안은 "20m/s로 올림".

### 연출 (우선순위 순)

1. **패럴랙스 3층**: 먼 배경(구름 ×0.1, 언덕·나무 ×0.5), 도로(×1), 화면 맨 아래를 스치는 전경(풀·울타리 기둥 ×1.6). 전경이 가장 큰 효과를 낸다.
2. **도로의 고대비 반복 무늬**: 도로 위쪽 경계에 빨강·흰색 연석 줄무늬, 차선 점선을 더 진하고 촘촘하게. 지금의 차선은 너무 옅어 흐름이 잘 보이지 않는다.
3. **카트 반응**: 바퀴 회전을 실제 속도에 연동, 바퀴 뒤 먼지·배기 입자, 속도선 길이와 개수를 속도 배율에 비례, 부스터 때 앞으로 기울고 감속 때 뒤로 처짐.
4. **부스터 카메라**: 카메라가 `base`를 약간 늦게 따라가 카트가 화면 앞쪽으로 튀어나갔다가 돌아오는 느낌. 화면 가장자리에 가로 줄무늬, 살짝 줌아웃(약 8%).
5. **출발 연출**: 카운트다운 직후 바퀴 연기와 짧은 가속.
6. 같은 트랙을 달리는 상대를 추월하거나 추월당하는 장면 자체가 상대 속도감을 만든다. 3장의 구현으로 자연히 얻는다.

효과음은 후속 작업으로 넣었다. 오디오 파일 없이 Web Audio로 합성한다(`game.js`의 소리 섹션). 한 기기를 같이 쓰므로 엔진음은 하나만 두고 전체 평균 속도 배율을 따라가며, 그 밖에 버튼·카운트다운·부스터·공격 획득·발사(날아가는 1초 동안의 휘파람이 공격 예고를 겸한다)·명중·빗나감·충돌·승리 소리가 있다. 배경 음악과 음소거 버튼은 없다. 음량은 `CONFIG.volume`과 `SOUNDS`의 값이며 실기기에서 들어 보고 조정한다.

성능: 6인 기준 패널 6개 × 카트 6대에 패럴랙스가 더해진다. 아이패드에서 프레임이 떨어지면 카트를 색·포즈별 오프스크린 캔버스에 미리 그려 재사용한다. 떨어지기 전에는 하지 않는다.

## 7. 구현 안내 (`game.js`)

빌드 없는 단일 파일 구조와 `CONFIG` 상수 블록은 유지한다. 바뀌는 함수:

| 함수 | 변경 |
|---|---|
| `newRace` | 플레이어 필드를 `base, off, lat, tOff, tLat`로 교체. 출발 시 `lat` 분산 |
| `makeItems` | 공유 아이템, 줄 단위 배치, `takenBy` |
| `moveKarts` | `off`·`lat` 이동, 전후·좌우 속도 분리 |
| `updateRace` | 속도 가감속, 따라잡기 보정, 공유 획득 판정과 동시 접촉 처리, `wx` 기준 결승 |
| `fire`, `resolveShot` | 대상의 `base` 상대 좌표로 기록·판정 |
| `kartPx` | 보는 사람(viewer)과 대상(target)을 받아 화면 좌표를 계산하도록 일반화 |
| `steer`, `drawPad` | 가로축을 `off` 범위에 대응 |
| `drawDrive` | 보는 사람 기준 카메라. 전체 카트·아이템·투사체·효과를 월드에서 그림. 자기 표식, 화면 밖 상대 표시, 패럴랙스 |
| `drawRoad`, `drawKart` | 연석·차선·전경, 속도 연동 연출 |
| `rankOf`, `drawBar`, `finish`, `showResult` | `dist` 대신 `wx` |

입력 처리(포인터 귀속, 공격 버튼, 일시정지), 화면 전환, 결과·승수 로직은 바꾸지 않는다.

## 8. 완료 기준

기존 기준(02 문서)에 더해 다음을 확인한다.

- 두 카트가 가까이 있을 때 서로의 화면에 상대가 같은 상대 위치로 보인다. A 화면에서 B가 5m 앞이면 B 화면에서 A는 5m 뒤다.
- 시야 밖 상대는 가장자리 표시로 방향과 거리 차를 알 수 있다.
- 한 카트가 획득한 아이템은 모든 화면에서 즉시 사라지고, 뒤따르던 카트가 같은 자리를 지나도 획득되지 않는다.
- 같은 프레임 동시 접촉에서 아이템이 정확히 한 명에게만 돌아간다.
- 결승선 그림을 넘는 순간과 승리 판정 순간이 일치한다.
- 공격의 경고 방향이 공격자가 있는 쪽과 일치하고, 피하면 맞지 않는다.
- 선두가 아닌 플레이어도 한 판에 아이템을 여러 번 얻을 수 있다.
- 기본 속도에서 도로 무늬·전경이 끊김 없이 흐르고, 부스터 발동과 종료를 화면만 보고 알 수 있다.
- 아이패드 6인에서 프레임 저하 없이 동작한다(실기기 확인).

### 검증 방법

첫 구현은 `playwright-core`와 시스템 Chrome(헤드리스)으로 검증했다. 합성 `PointerEvent`를 서로 다른 `pointerId`로 캔버스에 보내 멀티터치를 흉내 내고, 전역 함수 `update(dt)`를 직접 호출해 시간을 빨리 감았으며, `window.game` 상태를 읽어 판정했다. 당시 스크립트는 임시 폴더에 있어 남아 있지 않으므로 같은 방식으로 다시 작성한다. 실제 멀티터치 동작, 6손가락 동시 입력, iOS 제스처 충돌은 여전히 실기기 확인 대상이다.

확인 필요 항목의 답과, 구현하면서 추가한 규칙이다. 이 장이 위 본문과 충돌하면 이 장이 우선한다.

| 항목 | 결정 |
|---|---|
| ① 위치 모델 | B (2D 이동 유지) |
| ② 카트 충돌 | **넣음** (기본안과 다름. 아래 규칙) |
| ③ 따라잡기 보정 | 넣음 |
| ④ 기본 속도 | 20m/s로 올림. 봇 시뮬레이션 기준 한 판 약 45~50초 |

### 카트 충돌 규칙 (제안)

02 문서의 "카트끼리 직접 부딪히는 규칙은 넣지 않는다"와 3장의 "겹치면 통과한다"를 대체한다.

- 두 카트가 겹치면 **좌우(`lat`)로만** 서로 밀려난다. 반씩 밀려나고, 도로 가장자리에 막힌 쪽이 있으면 상대가 그만큼 더 밀려난다.
- 전진(`base`, `off`)은 막지 않는다. 길을 막아 순위를 굳히는 플레이를 만들지 않기 위해서다. 상대를 아이템 줄에서 밀어내는 것은 가능하다.
- 접촉 범위는 타원(전후 합 104단위, 좌우 합 18단위, 카트 그림 단위)이라 뒤에서 다가오면 서서히 옆으로 비켜난다. 6인 출발 정렬 간격(1/6)보다 좁아 출발 때는 닿지 않는다.
- 속도 불이익은 없다. 새로 닿는 순간 "툭" 연출만 한 번 나온다.

### 아이템 연속 획득 제한 (구현 중 추가)

4장의 규칙만으로 봇 시뮬레이션을 돌리면 4인·줄당 3칸에서 앞선 3대가 매 줄을 모두 가져가 꼴찌는 한 판에 0~2개만 얻었다(완료 기준 "선두가 아닌 플레이어도 여러 번 획득" 미달). 그래서 다음을 추가했다.

- 아이템을 얻은 카트는 **그 줄의 다른 칸과 바로 다음 줄**을 얻지 못한다(`canTake`).
- 얻을 수 없는 칸은 그 플레이어의 화면에서만 흐리게 보인다. 공격 보유 중의 공격 칸도 같다.
- 추가 후 시뮬레이션: 4인·6인 모두 전원이 한 판에 6~7개를 얻고, 선두와 꼴찌의 간격은 20~50m로 줄었다.

### 그 밖의 구현 메모

- 출발선·결승선은 카트 앞코가 닿는 자리에 그린다(`NOSE`). 앞코가 결승선에 닿는 프레임에 `wx ≥ 1000` 판정이 난다.
- 카운트다운 중에는 좌우로만 움직인다. 전후 목표는 출발 뒤에 반영되어 출발 전에 앞서 나갈 수 없다.
- 머리 위 번호는 모든 카트에 붙이고(공격 대상 번호 확인용), 자기 카트만 ▼가 더 붙는다.
- 머리 위 표식과 전경 자리를 위해 카트 크기를 주행 화면 높이의 50%에서 44%로 줄였다.
- 검증 스크립트는 이번에는 `tests/verify.js`에 남겼다. `cd tests && npm install && npm test`로 실행한다(시스템 Chrome 필요).
- 미구현: 6장 성능 항목의 오프스크린 캔버스 캐시(프레임 저하 확인 전에는 하지 않기로 한 항목).
